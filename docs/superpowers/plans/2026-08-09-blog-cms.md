# Personal Blog CMS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a secure single-administrator MySQL CMS that edits, previews, imports, and statically publishes the existing Astro blog.

**Architecture:** Keep the Astro site at the repository root, add a React/Vite admin SPA in `apps/admin`, a Fastify API and publisher in `apps/cms`, and Zod contracts in `packages/contracts`. MySQL is canonical; a serialized publish worker exports published rows into an isolated Astro release workspace, verifies the build, and only then atomically activates it for nginx.

**Tech Stack:** Node.js 22+, TypeScript 7, React 19.2, Vite 8.2, Fastify 5.11, MySQL2 3.23, Zod 4.4, Vditor 3.11, Argon2 0.45, Vitest 4.1, Testing Library 16.3.

## Global Constraints

- The CMS supports exactly one administrator and does not implement roles.
- Create a new MySQL database named `blog_cms`; runtime uses a dedicated least-privilege database user.
- The admin/API bind to `127.0.0.1` until a domain and TLS are configured.
- Markdown is the canonical article body and existing Markdown/MDX source files are never deleted by migration.
- EasyImage 2.8.5 at the configured base URL handles image storage through a server-side upload proxy.
- A failed build must never change the currently active public release.
- Production secrets are read from environment variables and never committed.
- Use red-green-refactor for every behavior change.

## File Map

- `packages/contracts/src/*`: shared Zod schemas and inferred request/response types only.
- `apps/cms/src/domain/*`: pure post state, slug, version, and publishing decisions.
- `apps/cms/src/repositories/*`: repository interfaces and MySQL implementations.
- `apps/cms/src/services/*`: authentication, article orchestration, import, image proxy, and publishing workflows.
- `apps/cms/src/routes/*`: HTTP parsing, authorization, and response mapping.
- `apps/cms/src/db/*`: MySQL pool, migration runner, and ordered SQL migrations.
- `apps/cms/src/cli/*`: explicit create-admin, import, publish, and migration entrypoints.
- `apps/admin/src/api/*`: typed HTTP client.
- `apps/admin/src/features/*`: login, articles, editor, taxonomy, and publishing UI grouped by user task.
- `apps/admin/src/layout/*`: navigation shell and persistent deployment strip.
- `apps/admin/src/styles/*`: design tokens, reset, shell, and component styles.
- `ops/*`: environment example, systemd units, SSH tunnel, release directory, backup, and nginx handoff documentation.
